## 1. Vision general

Sound Space Plus (Rhythia) incluye soporte completo de Realidad Virtual a traves de la API **OpenVR (SteamVR)**. El sistema permite jugar el juego de ritmo dentro de un entorno inmersivo con tracking de cabeza y manos, interaccion con menus mediante raycast, y compatibilidad con multiples tipos de controlador.

### Caracteristicas principales

- **Backend OpenVR**: Integracion via el addon `godot-openvr` (v1.1.0) que provee acceso a SteamVR.
- **Tipos de controlador soportados**: Generic, Oculus Touch, HTC Vive, Valve Index (Knuckles), Holographic Controller y Gamepad.
- **Modo Fake VR**: Simulacion completa de VR sin headset, util para desarrollo y testing.
- **Soporte zurdo**: Cambio dinamico de mano primaria durante el juego.
- **Interaccion con menus**: Puntero laser (raycast) para navegar menus 2D proyectados en superficies 3D.

### Plataformas soportadas

El addon incluye binarios nativos para:
- **Windows 64-bit**: `libgodot_openvr.dll` + `openvr_api.dll`
- **Linux x11**: `libgodot_openvr.so` + `libopenvr_api.so`
- **macOS**: Directorio presente pero sin binarios incluidos (solo README).

## 3. VRPlayer.gd / VRPlayer.tscn

### Descripcion

`VRPlayer` es el componente central del sistema VR. Define la clase `VRPlayer` (registrada como `class_name`) y gestiona la jerarquia completa del jugador en realidad virtual.

### Estructura del nodo (VRPlayer.tscn)

```
VRPlayer (Spatial) [VRPlayer.gd]
+-- Origin (ARVROrigin) [world_scale = 2.0]
|   +-- Head (ARVRCamera) [fov = 83.16]
|   +-- LeftHand (ARVRController) [controller_id = 1]
|   |   +-- Mesh (MeshInstance) [LowCube.obj, escala 0.1]
|   |   |   +-- Outline (MeshInstance)
|   |   |   +-- HandTrail (Particles) [500 particulas, visible=false]
|   |   +-- Ray (RayCast) [Pointer.gd, cast_to = (0, 0, -36)]
|   |       +-- Beam (MeshInstance) [CylinderMesh, color cian semitransparente]
|   +-- RightHand (ARVRController) [controller_id = 2]
|       +-- Mesh (MeshInstance) [LowCube.obj, escala 0.1]
|       |   +-- Outline (MeshInstance)
|       |   +-- HandTrail (Particles) [500 particulas, visible=false]
|       +-- Ray (RayCast) [Pointer.gd, cast_to = (0, 0, -36)]
|           +-- Beam (MeshInstance) [CylinderMesh, color cian semitransparente]
+-- FakeOrigin (Spatial) [posicion Y=2, visible=false por defecto]
    +-- Head (Camera) [FakeVRHead.gd]
    +-- LeftHand (Position3D) [posicion (-0.6, -0.5, -1)]
    |   +-- Mesh / Outline / HandTrail (misma estructura)
    |   +-- Ray [Pointer.gd, misma configuracion]
    +-- RightHand (Position3D) [posicion (0.6, -0.5, -1)]
        +-- Mesh / Outline / HandTrail (misma estructura)
        +-- Ray [Pointer.gd, misma configuracion]
```

### Variables principales

```gdscript
onready var origin:Spatial = $Origin           # Nodo raiz de tracking
onready var head:Camera = $Origin/Head         # Camara (ARVRCamera o Camera normal)
onready var left_hand:Spatial = $Origin/LeftHand    # Controlador izquierdo
onready var left_ray:RayCast = $Origin/LeftHand/Ray # Raycast izquierdo
onready var right_hand:Spatial = $Origin/RightHand  # Controlador derecho
onready var right_ray:RayCast = $Origin/RightHand/Ray # Raycast derecho
var primary_ray:RayCast                        # Raycast activo (segun mano dominante)
```

### Logica de inicializacion (`_ready`)

1. Oculta el origen real (`Origin.visible = false`).
2. Si `Rhythia.fake_vr` es `true`, reasigna todas las referencias de nodos al `FakeOrigin` (que usa nodos `Position3D` y `Camera` normales en lugar de nodos ARVR).
3. Muestra el origen activo (`origin.visible = true`).
4. Invoca `update_primary_ray()` para configurar la mano dominante.
5. Habilita el procesamiento y establece `pause_mode = PAUSE_MODE_PROCESS` para que funcione incluso con el juego pausado.

### Cambio de mano dominante

```gdscript
func update_primary_ray():
    if Rhythia.vr_left_handed:
        primary_ray = left_ray
        left_ray.enabled = true
        right_ray.enabled = false
    else:
        primary_ray = right_ray
        left_ray.enabled = false
        right_ray.enabled = true
```

El cambio se dispara en `_process` al presionar la accion `vr_switch_hands`. Solo un raycast esta activo a la vez; el otro se desactiva completamente.

### Procesamiento por frame (`_process`)

Cada frame:
1. Detecta si se presiono `vr_switch_hands` para alternar la mano dominante.
2. Fuerza una actualizacion inmediata del raycast (`force_raycast_update()`).
3. Actualiza la representacion visual del haz (`update_beam()`).

## 4. MenuPointer.gd

### Descripcion

`MenuPointer` es un nodo `Area` que actua como pantalla interactiva en VR. Proyecta un `Viewport` con la interfaz 2D del menu sobre una superficie 3D y convierte las colisiones del raycast en eventos de input compatibles con la UI de Godot.

### Variables

```gdscript
onready var viewport:Viewport = get_node("Viewport")  # Viewport con la UI del menu
export(Vector2) var size                                # Tamano fisico de la pantalla en el mundo 3D
var last_screen_pos:Vector2 = Vector2(0,0)              # Ultima posicion del cursor en pantalla
var active:bool = false                                 # Indica si el cursor esta sobre esta pantalla
```

### Deteccion de actividad

En `_process`, el puntero se marca como activo si:
1. El `primary_ray` del `VRPlayer` esta colisionando con algo.
2. El colisionador es exactamente este nodo `Area` (`self`).

```gdscript
active = (Rhythia.vr_player.primary_ray.is_colliding() and
          (Rhythia.vr_player.primary_ray.get_collider() == self))
```

### Conversion de coordenadas 3D a 2D

Cuando el puntero esta activo, el sistema:

1. Obtiene el punto de colision en espacio global.
2. Lo transforma a coordenadas locales del `Area` mediante `global_transform.xform_inv()`.
3. Calcula un porcentaje normalizado (0-1) basado en el tamano de la pantalla.
4. Mapea el porcentaje al tamano en pixeles del `Viewport`.

```gdscript
var lp3 = global_transform.xform_inv(p)
var local_pos = Vector2(lp3.x, lp3.y)
var percent = Vector2(
    clamp((local_pos.x + (size.x/2.0)) / size.x, 0, 1),
    clamp(1.0 - ((local_pos.y + (size.y/2.0)) / size.y), 0, 1)
)
var screen_pos = Vector2(
    round(percent.x * viewport.size.x),
    round(percent.y * viewport.size.y)
)
```

### Inyeccion de eventos

- **Movimiento del raton**: Si la posicion en pantalla cambio, crea un `InputEventMouseMotion` con posicion, velocidad relativa y presion del trigger.
- **Clicks**: Al recibir la accion `vr_click`, crea un `InputEventMouseButton` con `BUTTON_LEFT` en la posicion actual.
- **Teclado**: Los eventos `InputEventKey` se pasan directamente al viewport.

### Cursor visual

- Posiciona un `MeshInstance` (`$Pointer`) en el punto de colision con un ligero offset Z (+0.001) para evitar z-fighting.
- Renderiza un `PointerTrail` (particulas) si `Rhythia.cursor_trail` esta habilitado.
- Respeta la escala del cursor (`Rhythia.cursor_scale`), el color personalizado (`Rhythia.cursor_color`), modo rainbow y texturas personalizadas.
- Carga texturas de cursor y trail desde `user://cursor` y `user://trail` si existen.

## 5. Pointer.gd

### Descripcion

Script simple que controla la visualizacion del haz laser (beam) del raycast. Extiende `RayCast` y esta adjunto a los nodos `Ray` de ambas manos.

### Funcionamiento

```gdscript
func update_beam():
    var dist = -cast_to.z                    # Distancia maxima del raycast (36 unidades)
    if is_colliding():
        dist = (get_collision_point() - global_transform.origin).length()  # Distancia real al impacto
    $Beam.mesh.height = dist                 # Ajusta la longitud del cilindro
    $Beam.transform.origin.z = -dist/2.0     # Centra el cilindro entre el origen y el punto de impacto

func _process(_delta):
    $Beam.visible = enabled                  # Solo visible si el raycast esta habilitado
```

El beam es un `CylinderMesh` con radio superior de 0.003 y radio inferior de 0.01, con material cian semitransparente (`Color(0, 1, 1, 0.627)`). Se rota 90 grados para alinearse con el eje Z negativo del raycast.

## 6. vrmenu.gd / vrmenu.tscn

### vrmenu.gd

Script minimo que resetea la posicion del `VRPlayer` al cargar el menu:

```gdscript
extends Spatial

func _ready():
    Rhythia.vr_player.transform = Transform()
```

Esto asegura que al volver al menu, el jugador siempre aparezca en la posicion de origen.

### vrmenu.tscn - Estructura

```
VRMenuHolder (Spatial) [vrmenu.gd]
+-- WorldEnvironment [background_mode = 1 (color)]
+-- PointerScreen (Area) [MenuPointer.gd, posicion (0, 2.75, -2)]
    +-- Viewport [1280x720, own_world=true, hdr=false, usage=0]
    |   +-- Menu (instancia de menu2.tscn)
    |   +-- Label [debug info, visible=false, UbuntuMono 64px]
    |       +-- ColorRect [fondo negro]
    +-- Screen (MeshInstance) [QuadMesh 3.2 x 1.8]
    +-- CollisionShape [BoxShape 1.6 x 0.9 x 0.25, offset Z=-0.25]
    +-- PointerTrail (Particles)
    +-- Pointer (MeshInstance) [QuadMesh 0.1 x 0.1]
```

### Detalles de la pantalla VR

- **Tamano fisico**: Quad de 3.2 x 1.8 unidades (relacion 16:9).
- **Viewport interno**: Resolucion 1280x720, mundo propio (`own_world`), HDR desactivado, flip vertical habilitado.
- **Posicion**: Flotando a 2.75 unidades de altura y 2 unidades de profundidad frente al jugador.
- **Colision**: Box ligeramente mas profundo que la pantalla para capturar raycasts.
- **Material**: `SpatialMaterial` unshaded con `ViewportTexture` que proyecta el contenido del Viewport.

## 7. FakeVRHead.gd

### Descripcion

Simula el tracking de cabeza VR usando el raton. Permite probar la experiencia VR sin necesidad de un headset real.

### Variables

```gdscript
var yaw = 0       # Rotacion horizontal acumulada
var pitch = 0     # Rotacion vertical acumulada (limitada a -89..89 grados)
var active = false # Si el modo de captura del raton esta activo
```

### Control de rotacion

Al recibir `InputEventMouseMotion` o `InputEventScreenDrag` (cuando `active` es true):

```gdscript
yaw = fmod(yaw - event.relative.x * Rhythia.sensitivity * 0.2, 360)
pitch = max(min(pitch - event.relative.y * Rhythia.sensitivity * 0.2, 89), -89)
get_parent().rotation = Vector3(deg2rad(pitch), deg2rad(yaw), 0)
```

- La rotacion se aplica al nodo padre (el FakeOrigin), no a la camara directamente.
- La sensibilidad se escala por `Rhythia.sensitivity * 0.2`.
- El pitch se limita a +/- 89 grados para evitar gimbal lock.

### Activacion

- Presionar `fc_trigger` alterna entre modo activo (raton capturado) e inactivo (raton visible).
- En `_ready`, habilita o deshabilita `_process` y `_process_input` segun `Rhythia.fake_vr`.
- En `_process`, fuerza la camara como actual (`make_current()`) si no lo esta.

### ovr_main.gd (referencia)

Aunque Rhythia no usa directamente `ovr_main.gd`, este script muestra el patron estandar de inicializacion OpenVR:

1. Carga `OpenVRConfig.gdns` y configura el action set.
2. Busca la interfaz "OpenVR" via `ARVRServer.find_interface("OpenVR")`.
3. Inicializa la interfaz y configura el viewport para ARVR.
4. Desactiva vsync y ajusta la tasa de fisicas a 180 Hz (90 Hz * factor 2).

### ovr_controller.gd

Gestiona la visibilidad de los controladores ARVR segun su estado de activacion. Oculta el controlador cuando no esta activo y emite la senal `controller_activated` cuando se detecta.

### ovr_render_model.gd

Carga dinamicamente la malla del modelo de render del controlador fisico del usuario. Intenta cargar el modelo especifico del controlador, y si no lo encuentra, cae al modelo generico `generic_controller`. Aplica la escala del mundo ARVR automaticamente.

### Variables VR en Rhythia.gd

```gdscript
# En scripts/Rhythia.gd (singleton autoload)

var vr:bool = false                                # VR activo

var vr_available:bool = false                      # Interfaz OpenVR detectada

var vr_left_handed:bool = false                    # Mano izquierda como primaria
var vr_controller_type:int = Globals.VR_GENERIC    # Tipo de controlador VR
```

### Enum de tipos de controlador (Globals.gd)

```gdscript
# En scripts/Globals.gd
enum {
    VR_GENERIC   # = 0 - Controlador generico
    VR_OCULUS    # = 1 - Oculus Touch
    VR_VIVE      # = 2 - HTC Vive
}
```

### Deteccion de disponibilidad VR

Durante la inicializacion de Rhythia, se busca la interfaz OpenVR:

```gdscript
# En Rhythia.gd, durante la inicializacion
emit_signal("init_stage_reached", "Check VR status")
yield(get_tree(), "idle_frame")

var interface = ARVRServer.find_interface("OpenVR")
if interface:
    vr_interface = interface
    vr_available = true
```

Si se encuentra, `vr_available` se establece a `true` y se guarda la referencia a la interfaz. Esto no inicia VR automaticamente; el usuario debe activarlo manualmente.

### Metodo start_vr()

Este metodo inicia el modo VR completo. Se invoca desde el boton "StartVR" del `Sidebar` del menu.

```gdscript
func start_vr():
    if vr:
        print("VR already active")
        return
    print("VR START")
    vr = true

    # Configuracion de rendimiento
    get_viewport().hdr = false
    OS.vsync_enabled = false
    Engine.target_fps = 90
```

#### Modo Fake VR (Shift presionado al iniciar)

Si el usuario mantiene `Shift` al presionar "Start VR":

```gdscript
if Input.is_key_pressed(KEY_SHIFT):
    OS.window_maximized = true
    fake_vr = true
    # Bind: tecla F para cambiar de mano
    InputMap.action_add_event("vr_switch_hands", ev)  # KEY_F
    # Bind: click izquierdo para vr_click
    InputMap.action_add_event("vr_click", ev)         # BUTTON_LEFT
```

#### Modo VR real

Sin Shift, se inicializa la interfaz ARVR real:


#### Instanciacion del VRPlayer

En ambos modos (real y fake), al final:

```gdscript
var vr_av:VRPlayer = load("res://vr/VRPlayer.tscn").instance()
rootg.add_child(vr_av)
vr_av.name = "VRPlayer"
```

### Cursor VR en gameplay (NoteManager.gd)

Durante el juego, el cursor VR se calcula mediante la funcion `do_vr_cursor()`:

```gdscript
func do_vr_cursor():
    var centeroff = Rhythia.vr_player.primary_ray.get_collision_point() + cursor_offset
```


El punto de colision del rayo primario del jugador VR se utiliza directamente como posicion del cursor en la grilla de juego.

## 11. ARVRAvatar.tscn

### Descripcion

Escena prefabricada ubicada en `prefabs/ARVRAvatar.tscn`. Representa un avatar simplificado del jugador VR con una estructura basica de tracking.

### Estructura

```
        |   +-- trail (Particles) [500 particulas, visible=false]
```

### Diferencias con VRPlayer.tscn

| Aspecto | ARVRAvatar.tscn | VRPlayer.tscn |
|---------|-----------------|---------------|
| Script adjunto | Ninguno | `VRPlayer.gd` |
| FakeOrigin | No incluido | Incluido con `FakeVRHead.gd` |

`ARVRAvatar.tscn` es una version anterior o simplificada del avatar VR. La implementacion activa del juego utiliza `VRPlayer.tscn`.

## Notas adicionales

- **Persistencia del VRPlayer**: El nodo `VRPlayer` se anade al nodo raiz global (`rootg`), no a escenas individuales. Esto permite que persista entre transiciones de escena sin ser destruido.
- **Pause mode**: El `VRPlayer` usa `PAUSE_MODE_PROCESS` para seguir procesando durante pausas del juego, lo cual es esencial para mantener el tracking y la interaccion con menus de pausa.
- **World scale**: Tanto `VRPlayer.tscn` como `ARVRAvatar.tscn` usan `world_scale = 2.0` en el `ARVROrigin`, lo que duplica la escala del mundo VR respecto al mundo real.
- **Raycast range**: Todos los raycasts tienen un `cast_to` de `(0, 0, -36)`, lo que les da un alcance de 36 unidades en la direccion Z negativa (adelante del controlador).
- **Compatibilidad unidireccional**: VR es un modo de entrada alternativo. Una vez activado, el juego redirecciona todas las cargas de menu al menu VR (`vrmenu.tscn`). No existe un mecanismo para volver al modo desktop sin reiniciar.
